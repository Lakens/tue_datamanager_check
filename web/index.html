TU/e Data Manager Check

Check a data package against TU/e's archiving guidelines before archiving it through RAPS

Upload a data package, as a folder or a .zip file, and receive a report that checks it the way TU/e's data managers do: its components and structure, its README against the TU/e template, ethical approval and consent when people took part, and its files (formats, names, junk files, personal data, codebook, missing values and code). The check runs with metacheck on SURF Research Cloud in the Netherlands, with an open source language model on that server.

Check a data package

Drop the package folder or a .zip file here

Your browser packs a folder into a .zip before uploading it, at most 500 MB (1000 MB unpacked). Everything in it is sent, also hidden files such as .DS_Store, because the check looks for those too.

What happens to your files

The package goes to the metacheck server on SURF Research Cloud and nowhere else, with one exception: to decide whether people took part, up to 3 of the package's scientific documents (such as the manuscript) may be converted to text by TU/e's GROBID server. The uploaded package is deleted as soon as the check has read it, and the report is kept for one hour. A report can only be fetched with its random job number, which only your browser knows.

About the check

The checks follow TU/e's archiving guidelines in Research Cockpit and the RDLC document "Using Metacheck for data package review and paper analysis". Every decision behind them is described in the tue_datamanager_check repository, where you can also run the check on your own computer.

tue_datamanager_check is a module for metacheck, open source software by scienceverse.
